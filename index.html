DSA Roadmap — end to end

~9 months, 1–2 hrs/day sustained

A topic-ordered, week-by-week path from zero patterns to Google/Amazon-ready. Each stage builds on the last — don't skip ahead to graphs/DP without arrays and recursion solid, the patterns compound.

Stage 1 — Foundations: Arrays, Strings, Hashing
Weeks 1–4 · ~40 problems
▶

Patterns to master

  • Two pointers (sorted array pairs, container with most water, trapping rain water)
  • Sliding window (fixed + variable size — longest substring problems, subarray sums)
  • Prefix sums, Kadane's algorithm
  • HashMap/HashSet patterns — frequency counting, two-sum family, grouping (anagrams)
  • String manipulation — reversal, palindrome checks, pattern matching basics

Milestone problems

  • Two Sum, 3Sum, Longest Substring Without Repeating Characters, Group Anagrams, Product of Array Except Self, Trapping Rain Water

Resources

NeetCode Roadmap — Arrays & Hashing, Two Pointers, Sliding Window sections LeetCode Study Plans — "Top Interview 150"
Checkpoint: solve a fresh Medium array/string problem in under 20 minutes without hints before moving on.
Stage 2 — Recursion, Backtracking, Stacks/Queues
Weeks 5–7 · ~30 problems
▶

Patterns to master

  • Recursion fundamentals — base case, recursive tree visualization, recursion vs iteration tradeoffs
  • Backtracking — subsets, permutations, combinations, N-Queens, word search
  • Stack patterns — valid parentheses, monotonic stack (next greater element), min stack
  • Queue/Deque — sliding window maximum, circular queue design

Milestone problems

  • Subsets, Permutations, Combination Sum, N-Queens, Daily Temperatures, Largest Rectangle in Histogram

Resources

NeetCode Roadmap — Stack, Backtracking sections
Stage 3 — Linked Lists, Trees, Binary Search Trees
Weeks 8–11 · ~40 problems
▶

Patterns to master

  • Linked list manipulation — reversal, cycle detection (Floyd's), merge, LRU cache design
  • Tree traversals — inorder/preorder/postorder (recursive + iterative), level order (BFS)
  • BST properties — validate BST, insert/delete, kth smallest, LCA
  • Tree construction problems (build tree from traversals), tree diameter/depth patterns

Milestone problems

  • Reverse Linked List, LRU Cache, Validate BST, Lowest Common Ancestor, Binary Tree Level Order Traversal, Serialize/Deserialize Binary Tree

Resources

NeetCode Roadmap — Linked List, Trees sections
Checkpoint: LRU Cache from scratch, no hints, correct on first compile — this exact problem is asked constantly at Amazon/Microsoft.
Stage 4 — Graphs (the highest-leverage topic)
Weeks 12–16 · ~45 problems
▶

Patterns to master

  • BFS/DFS on grids and graphs — connected components, flood fill, Number of Islands (and its many variants — this shows up constantly at Amazon)
  • Topological sort (course schedule problems), cycle detection (directed + undirected)
  • Union-Find (Disjoint Set) — redundant connection, accounts merge
  • Shortest path — Dijkstra, Bellman-Ford basics, BFS for unweighted shortest path
  • Minimum Spanning Tree basics (Prim's/Kruskal's) — lower priority, know conceptually

Milestone problems

  • Number of Islands (+ variants), Course Schedule I/II, Clone Graph, Network Delay Time, Word Ladder, Redundant Connection

Resources

NeetCode Roadmap — Graphs, Advanced Graphs sections cp-algorithms.com — graph algorithm references
Why this stage matters most: graph variations appear in nearly every Amazon and Google interview reported in 2026. Spend extra time here over any other topic if time is short.
Stage 5 — Dynamic Programming
Weeks 17–22 · ~50 problems
▶

Patterns to master, in order

  • 1D DP — climbing stairs, house robber, decode ways (build the "recursion → memoization → tabulation" muscle here first)
  • Knapsack family — 0/1 knapsack, coin change, partition equal subset sum
  • 2D DP — unique paths, longest common subsequence, edit distance
  • String DP — palindrome partitioning, word break, longest palindromic substring
  • DP on intervals, DP with state machines (buy/sell stock variants)

Milestone problems

  • House Robber, Coin Change, Longest Common Subsequence, Edit Distance, Word Break, Best Time to Buy/Sell Stock (all variants)

Resources

NeetCode Roadmap — 1-D DP, 2-D DP sections Aditya Verma — Dynamic Programming playlist (pattern-based)
Checkpoint: for any new DP problem, you should be able to define the state and transition within 5 minutes, even if the full solve takes longer. This is what interviewers actually watch for.
Stage 6 — Heaps, Tries, Intervals, Bit Manipulation
Weeks 23–26 · ~30 problems
▶

Patterns to master

  • Heaps — kth largest element, top K frequent, merge K sorted lists, median from data stream
  • Tries — implement trie, word search II, autocomplete-style problems
  • Intervals — merge intervals, meeting rooms, insert interval
  • Bit manipulation — single number, counting bits, XOR tricks (lower priority, know basics)

Milestone problems

  • Kth Largest Element, Merge K Sorted Lists, Implement Trie, Merge Intervals, Meeting Rooms II

Resources

NeetCode Roadmap — Heap, Trie, Intervals sections
Stage 7 — Mock interviews & timed drilling
Weeks 27–36 · ongoing, 2–3x/week
▶

What to do

  • Re-solve Hard problems across all topics above, timed at 30–35 minutes each
  • Do 2 timed mock interviews per week (Pramp free, or interviewing.io paid) — practice narrating your approach out loud, not just solving silently
  • Keep an error log: every problem you fail or need hints on, note the pattern you missed and revisit it a week later
  • Company-specific: run through recent LeetCode "Discuss" posts tagged with your target company for the last 3–6 months

Resources

Pramp — free peer mock interviews interviewing.io — mock interviews with engineers LeetCode Discuss — company-tagged recent interview questions
Total volume by the end: roughly 235–260 problems across all stages if you do every milestone problem plus 2–3 similar ones per pattern. That lines up with the Google/Amazon bar from the company table below — hitting it covers every other company on your list too.

System Design Roadmap — end to end

~4 months, starts after DSA Stage 4

LLD and HLD are different skills tested separately in most loops. Build LLD first (it's more mechanical and pattern-based), then HLD (which needs LLD's building blocks plus distributed-systems concepts).

Weeks 1–3
▶

Topics

  • SOLID principles — with real code examples in Java, not just definitions
  • Creational patterns — Factory, Builder, Singleton (and why naive Singleton is a red flag in interviews)
  • Structural patterns — Adapter, Decorator, Facade
  • Behavioral patterns — Strategy, Observer, State — these three come up constantly in LLD interviews
  • UML basics — class diagrams, relationships (association, aggregation, composition)

Stage 2 — LLD practice problems (code them, don't just read)
Weeks 4–7 · 8–10 problems, fully coded
▶

Problems to build end-to-end in Java

  • Parking Lot system (classic — Amazon, Microsoft favorite)
  • Elevator System
  • Library Management System
  • Rate Limiter (token bucket / sliding window algorithms) — Microsoft favorite
  • LRU Cache as a full class design (not just the LeetCode DSA version)
  • BookMyShow / movie ticket booking system (Amazon favorite)
  • Splitwise / expense sharing system
  • Logging framework

Stage 3 — Distributed Systems Building Blocks (HLD base)
Weeks 8–11
▶

Topics — learn each concept + when to use it + its tradeoffs

  • Scaling — vertical vs horizontal, load balancers (round robin, least connections, consistent hashing)
  • Caching — cache-aside, write-through, write-back, eviction policies, Redis/Memcached use cases
  • Databases — SQL vs NoSQL tradeoffs, indexing, sharding strategies, replication (master-slave, master-master)
  • CAP theorem — and being able to argue which two you'd pick for a given system, with real justification
  • Message queues — Kafka vs RabbitMQ, when to use pub-sub vs point-to-point
  • Consistency models — strong vs eventual consistency, idempotency
  • Rate limiting, API gateway patterns, CDNs
  • Back-of-envelope estimation — practice quick math for QPS, storage, bandwidth given user counts

Resources

System Design Primer (GitHub) — read cover to cover Gaurav Sen — System Design YouTube series High Scalability — real company architecture case studies

Weeks 12–15 · 10–12 problems
▶

Problems to design end-to-end

  • URL Shortener (the canonical starting problem)
  • Rate Limiter (as a distributed system, not just the algorithm)
  • Design Twitter/X feed (fan-out on write vs read)
  • Design a notification system (push, email, SMS at scale) — Amazon favorite
  • Design an Instagram/photo-sharing service
  • Design a ride-sharing dispatch system — Uber favorite

  • Design a payment/wallet processing system with idempotency — PayPal/JPMorgan favorite

Add-on for AI/ML-track applications (Applied Scientist / ML Engineer roles)

Every company above, when hiring for an ML-adjacent role, adds an ML system design round on top of the software HLD/LLD above — it does not replace it. Prepare: designing a recommendation system end-to-end, a fraud/risk scoring pipeline, a search ranking system, and (your strongest ground) a RAG-based support/search system at scale — covering data pipeline, feature store, model serving, retraining cadence, and monitoring/drift detection.

Practical takeaway: prepare LLD (SOLID, design patterns, one clean end-to-end class design you can adapt) and HLD (scalability, caching, DB choice, back-of-envelope math) as two separate skills. Do at least 10 HLD mocks and 6 LLD mocks before applying broadly — this is where most experienced candidates lose otherwise-strong loops.
Phase 6

Interview Sprint

Month 18 – 22

Dedicated, focused prep right before applying — mocks, behavioral prep, and closing gaps.

Coding rounds

  • Timed mock interviews (Pramp, interviewing.io)
  • Explain your approach out loud before coding — practiced explicitly
  • Revisit weak DSA topics identified from mocks

ML / applied science rounds

  • Be ready to derive backprop, explain bias-variance, overfitting fixes on a whiteboard
  • Walk through your RAG/agent projects in deep technical detail — evaluation choices, failure modes, tradeoffs made
  • Practice "how would you improve this model/system" follow-ups

System design rounds

  • 5–8 mock system design sessions, mix of software + ML system design
  • Always clarify requirements first, discuss tradeoffs out loud, don't jump to a solution

Behavioral

  • STAR method stories for: conflict, failure, leadership, ambiguity — 6–8 stories covering all angles
  • Amazon: map every story explicitly to a Leadership Principle
  • Have a clear, honest narrative for the TCS → product company → target company career story
Referrals matter more than cold applications. Build genuine connections on LinkedIn with engineers at target companies months before applying — a referral changes your odds of even getting a first screen dramatically, especially coming from a service company background.
